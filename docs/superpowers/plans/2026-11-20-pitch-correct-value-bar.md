# Pitch Correct Value Bar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** In Fancy Pitch Correct, the top bar's Correction group becomes a value bar that edits the defaults when no note is selected and the selected notes otherwise, with direct drags (no edit popups), a range fill under each value, a "Timing" row for the four less-used values, purpose-first tooltips, and a note menu whose every value row writes to all selected notes.

**Architecture:** One table, `BAR_VALUES`, describes the seven values (key, range, format, where it applies, tooltip). One view function, `bar_view(spec)`, answers "what does this control show and what would a drag write to" from the selection; one widget, `draw_value(spec)`, draws any of the seven on the existing `param_drag`, with the fill drawn on the item's rectangle. The header's plan table (`HDR_PLANS`) places the units; the Timing row is one more bar row shown while `state.timing_open` is true.

**Tech Stack:** Lua 5.4, ReaScript API, ReaImGui, `_lib/theme.lua` (read only).

**Spec:** `docs/design/pitch-correct-value-bar.md` (Approved 2026-11-20, TheFancyWolf). Implement it exactly. Do not invoke skills.

## Review Focus

1. **Selection changes during a bar drag** (undo, redo, another item selected, analysis started, a note deleted by Merge). The drag is dropped and nothing indexes a note that is gone. (Task 1, test e.)
2. **A relative drag that hits the end of the range.** Notes at 90% and 40% dragged up by 30: they read 100% and 70%; dragging back down in the same gesture returns them to 90% and 40%, not 70% and 40% (each note is computed from its value at the start of the drag). (Task 1, test c.)
3. **Esc in the middle of a multi-note drag.** Every note returns to its own earlier value, including notes that had no own value (they inherit again, they do not keep a copy of the inherited number); no undo point, no envelope write. (Task 1, test d.)
4. **A default edited while another item is open elsewhere in the session.** The status message still says "not undoable" and how many items are outdated, exactly as before the change. (Task 1, test b.)
5. **Narrow docked width with the Timing row open and a long item name.** No control overlaps or leaves the window; only the item badge truncates. (Task 2, test c.)

### Task 1: The value model, the value control, and the three always-visible values

**Files:** Modify `Pitch/Fancy_Pitch Correct.lua` — the TOP BAR CONTROLS block (`BAR_SCOPE_TAGS`, `BAR_BADGES`, `K.bar_measure`, `K.bar_frame`: `cascade_view`, `level_colors`, `write_cascade_value`, `reset_cascade_param`, `item_override_menu`, `draw_retune`, `draw_badge`), the TOP BAR block (`HDR_CORR_FULL`, `HDR_CORR_FOLDED`, `HDR_GROUP`), the section comment at "TOP BAR".

**Interfaces — Produces** (all inside the top bar controls `do` block unless prefixed `K.`):
- `BAR_VALUES` — array of specs, in this order: `tighten`, `retune_speed`, `tolerance`, `transition_ms`, `onset_ramp_ms`, `scoop_shape`, `legato_threshold_ms`. Each: `{ id, key, label, lo, hi, scale, fmt, tip, levels }` where `id` ∈ `"tight" "strength" "tol" "trans" "ramp" "scoop" "legato"`; `label` is the bar label from the Copy deck (`"Strength"` for `retune_speed`); `scale` is 100 for the three values stored 0..1, else 1; `fmt` is the value's format without the label; `tip` is the Copy deck's purpose sentence; `levels` is `"note"` (Tighten, Scoop Shape: notes only), `"item"` (Legato Gap: defaults and item only) or `"all"`. `BAR_VALUE_BY_ID[id]` indexes it. `timing = true` on the last four.
- `bar_sel_notes() -> notes, count` — the selected notes that have `controls`, in time order, written into one reused table (no table per frame).
- `bar_view(spec) -> view` — fills and returns one reused table per spec: `{ lo_v, hi_v, mixed, level, disabled, reason, target }` in display units. `target` is `"notes"` when `count > 0`, else `"item"` when the take has an override for the key, else `"default"`. `level` is `"note"` when any selected note has its own value, `"item"` for an item override, else `"global"`. `disabled`/`reason`: the inspector reason first; then `levels == "note"` with no selection → "Select notes to change it ({Mod}+A selects all)"; `levels == "item"` with a selection → "Set per item: press Esc to deselect, then change it". With a selection, `lo_v`/`hi_v` are the lowest and highest effective value of the selected notes and `mixed = lo_v ~= hi_v`.
- `bar_write(spec, view, delta | nil, typed | nil)` — while dragging: default/item targets take the absolute value; the `"notes"` target sets each note to `clamp(start_value + delta)` from the per-note values remembered when the press began (`state.bar_edit = { id, raws = { [note] = raw | false }, starts = { [note] = effective } }`), storing `nil` for a zero Tighten. A typed value sets every note to it. `bar_commit(spec, view)` writes once on release: `apply_envelope_to_take("Adjust " .. PARAM_LABELS[key])`, plus `K.save_settings("cascade")` and the existing `note_global_edit(key)` for the default target. `bar_cancel(spec)` (Esc) puts every `raws` entry back (`false` → `nil`) and writes nothing. `bar_reset(spec, view)`: notes → every selected note's own value cleared, one undo point `"Reset " .. name`, no undo point when none had one; otherwise the existing `reset_cascade_param(key)`.
- `state.bar_edit` is cleared wherever `state.context_edit` is cleared on a model reload (the line near `state.context_edit = nil` in the reload path), so a drag cannot outlive its notes.
- `K.bar_value_fill(bctx, lo_frac, hi_frac, color)` — on the item just submitted: a track of height `L.xs` across the bottom inside the frame in `P.outline`, and a filled segment `lo_frac..hi_frac` in `color` (`lo_frac = 0` when not mixed). Nothing when the control is disabled.
- `draw_value(spec)` — `Theme.align`, `BeginDisabled(view.disabled)`, `param_drag(bctx, "bv_" .. spec.id, nil, anchor, spec.lo, spec.hi, text)` at width `s.unit_w[spec.id]`, where `text` is the whole visible string (`"Strength 80%"`, `"Tighten 20–60%"`, `"Tighten –"`, plus `" *"` when `view.level ~= "global"`) with `%` doubled, and `anchor` is `view.lo_v`. Then the fill (colour by level: `P.text_dim` / `P.accent` / `P.accent2`), `K.setting_hint(bctx, spec.key, active, set)` over the affected notes, the tooltip (purpose line, the scope line for `view.target` and count, the gesture line; a disabled control shows purpose + reason with `HoveredFlags_AllowWhenDisabled`; Tolerance adds "Used once Tighten is above 0%." when every selected note's Tighten is 0), and the right-click menu: default/item → the existing two entries; notes → one entry "Reset to inherited" (`levels == "note"`: "Reset to 0%") calling `bar_reset`.
- `draw_pill()` — `Theme.badge`, fixed width `s.unit_w.pill` measured from `Defaults`, `1 note`, `999 notes`; text `Defaults` / `1 note` / `%d notes`; neutral colours with no selection, `P.accent2` with `Theme.label_on` with one; tooltip from the Copy deck.
- `K.bar_measure`: `s.unit_w[id]` for each of the seven = widest of `label .. " " .. fmt(lo)`, `fmt(hi)` and the mixed text `fmt(lo) – fmt(hi)`, plus `" *"`, plus `s.pad_x`. `s.unit_w.pill` as above. `s.slider_w`, `s.scope_w`, `s.unit_w.retune` go.
- `K.bar_frame`'s `draw_unit(id)` now answers `"pill"`, `"tight"`, `"strength"`, `"tol"` (and still `"trans"`, `"ramp"`, `"legato"`, `"timing"` until Task 2). `HDR_CORR_FULL = { "pill", "tight", "strength", "tol", "trans", "ramp", "legato" }`, `HDR_CORR_FOLDED = { "pill", "tight", "strength", "tol", "timing" }`; `HDR_GROUP` updated. `draw_retune`, the Tolerance entry of `BAR_BADGES`, `BAR_SCOPE_TAGS`, `BAR_STRENGTH_LABEL` and `BAR_REASON_NOTE_OVERRIDE` are deleted.
